Weblium чи Claude + GitHub: на чому запускати сайт у 2026 році

Порівнюю два способи, якими я запускаю сайти: конструктор Weblium і власний код із Claude на GitHub. Ціни, можливості, переваги, недоліки і прості правила вибору.

Мене часто питають: «А на чому краще робити сайт?» Я запускаю сайти двома способами: на конструкторі Weblium і як власний код, який я пишу разом із Claude і розміщую на GitHub. На Weblium я зробив десятки сайтів для клієнтів, а на Claude + GitHub працює, наприклад, цей сайт, браузерна гра Project X і карта Cyber Kyiv.

Обидва підходи робочі, але вони дуже різні: за грошима, за свободою, за тим, хто і як редагує сайт після запуску. Розберу чесно, без «мій спосіб найкращий».

Коротка відповідь

Якщо тобі потрібен типовий сайт для бізнесу — лендинг, сайт послуг, невеликий магазин — і ти хочеш сам змінювати тексти й фото у візуальному редакторі, обирай Weblium.

Якщо потрібна нестандартна логіка (база даних, особистий кабінет, гра, інтерактивна карта, автоматизації), максимальна швидкість і мінімум щомісячних платежів — обирай Claude + GitHub.

А тепер детально.

Що таке Weblium

Weblium — це український конструктор сайтів. Ти обираєш шаблон, збираєш сторінку з готових блоків і редагуєш усе мишкою: тексти, фото, кольори, кнопки. Хостинг, SSL-сертифікат і технічна частина — на боці платформи.

Безкоштовно сайт на Weblium можна тримати лише обмежений час: за умовами платформи він живе до 60 днів, далі потрібен платний тариф. Станом на осінь 2026 року тарифи такі:

  • Starter — 16 доларів на місяць або 11 доларів на місяць при оплаті за рік: розширені SEO-налаштування, форми заявок, інтеграції, власний код;
  • Business — 25 доларів на місяць або 17,50 долара на місяць при оплаті за рік: додатково онлайн-магазин, блог і мультимовність до 5 мов.

Домен оплачується окремо.

Що таке Claude + GitHub

Тут немає конструктора. Сайт — це звичайні файли: HTML, CSS і JavaScript. Я пишу їх разом із Claude — штучним інтелектом від Anthropic, який уміє працювати з кодом, — а розміщую на GitHub Pages, безкоштовному хостингу від GitHub.

Щоб клієнт міг сам оновлювати контент, я роблю просту адмінку. Саме так працює цей сайт: статті й проєкти я додаю через власну адмінку, а частину статей узагалі публікує автоматизація.

Що це коштує:

  • хостинг GitHub Pages — безкоштовно;
  • домен — як і в будь-якому іншому випадку;
  • підписка на Claude потрібна тому, хто розробляє й змінює код. Тариф Pro коштує 20 доларів на місяць (або 17 доларів при оплаті за рік), але власнику готового сайту він не обов'язковий.

Переваги Weblium

Ти сам керуєш сайтом. Хочеш змінити ціну, фото чи додати блок — відкрив редактор і змінив. Без розробника і без очікування.

Швидкий запуск. Для лендинга чи сайту послуг не потрібно писати жодного рядка коду. Готові блоки, адаптив під телефони і SSL уже є.

Магазин і блог «з коробки». На тарифі Business можна запустити каталог, кошик і блог без сторонніх сервісів.

Підтримка платформи. Якщо щось зламалось на рівні хостингу, це питання до Weblium, а не до тебе.

Недоліки Weblium

Щомісячна плата назавжди. Поки сайт працює, ти платиш за тариф. За кілька років сума стає відчутною, особливо якщо сайтів кілька.

Обмеження конструктора. Нестандартна логіка — особистий кабінет, розрахунки, складні інтеграції, ігри — або неможлива, або робиться через обхідні шляхи.

Прив'язка до платформи. Сайт живе всередині конструктора. Якщо колись захочеш переїхати, сайт фактично доведеться робити заново.

Шаблонність. Сайти з однакових блоків легко впізнати. Це вирішується дизайном, але межі все одно задає конструктор.

Переваги Claude + GitHub

Майже нуль щомісячних витрат. GitHub Pages безкоштовний, платиш лише за домен.

Повна свобода. Можна зробити що завгодно: від простого лендинга до гри з базою гравців і серверною логікою, як у Project X, або карти, що оновлюється за розкладом, як Cyber Kyiv.

Швидкість. Статичний сайт завантажується дуже швидко, а це плюс і для відвідувачів, і для пошукових систем.

Код належить тобі. Усі файли лежать у твоєму репозиторії. Сайт можна перенести на будь-який хостинг за кілька хвилин.

Автоматизації. Сайт на власному коді легко поєднати з автоматизаціями на базі Claude: публікацією статей за розкладом, оновленням даних, звітами.

Недоліки Claude + GitHub

Немає візуального редактора. Тексти й фото можна змінювати через адмінку, але переставити блоки мишкою, як у конструкторі, не вийде. Серйозніші зміни — через розробника.

Обмеження GitHub Pages для бізнесу. За правилами GitHub, Pages не призначений для онлайн-бізнесу, інтернет-магазину чи сайтів, головна мета яких — комерційні транзакції. Сайт-візитка, портфоліо чи блог — нормально. Повноцінний магазин краще розміщувати на іншому хостингу або на конструкторі.

Ліміти хостингу. Сайт до 1 ГБ і м'який ліміт трафіку 100 ГБ на місяць. Для більшості сайтів цього з запасом, але для важких відео чи великих архівів — ні.

Без сервера. GitHub Pages віддає лише статичні файли. Якщо потрібні реєстрація, база даних чи оплати, підключаються окремі сервіси, наприклад Supabase, як я зробив у Project X.

Що обрати: прості правила

Обирай Weblium, якщо:

  • тобі потрібен лендинг чи сайт послуг, і ти хочеш сам його редагувати;
  • плануєш інтернет-магазин без складної логіки;
  • щомісячна підписка не проблема, а важливі простота й підтримка платформи.

Обирай Claude + GitHub, якщо:

  • потрібна нестандартна функціональність: база даних, гра, карта, розрахунки, автоматизації;
  • хочеш мінімум щомісячних платежів і повний контроль над кодом;
  • важлива максимальна швидкість сайту;
  • контент оновлюється нечасто або через адмінку.

Часті питання

Чи можна почати на Weblium, а потім перейти на власний код?

Так, але це буде новий сайт: дизайн і тексти можна взяти з поточного, а сам сайт доведеться зібрати заново.

Чи гірше SEO на конструкторі?

Ні. На Weblium є всі потрібні налаштування: заголовки, описи, адреси сторінок. Статичний сайт на GitHub трохи швидший, а в розмітці для пошукових систем немає обмежень, але переможе той сайт, у якого кращий контент.

Чи потрібно мені самому платити за Claude?

Ні, якщо сайт робить і підтримує розробник. Підписка потрібна тому, хто працює з кодом.

Що надійніше?

Обидва варіанти надійні. GitHub Pages — інфраструктура GitHub, якою користуються мільйони розробників, Weblium — платформа, яка відповідає за свої сервери. Різниця не в надійності, а в тому, хто контролює сайт.

Мій висновок

Я не вважаю, що один підхід «правильніший». Weblium — це зручність і самостійність для типового бізнес-сайту. Claude + GitHub — це свобода, швидкість і майже нульові витрати на утримання для проєктів, яким тісно в конструкторі.

Якщо не знаєш, що підійде саме тобі, опиши задачу — я підкажу чесно, навіть якщо відповідь буде «тобі вистачить конструктора». Детальніше про те, як я роблю сайти, — на сторінці розробки сайтів під ключ.
